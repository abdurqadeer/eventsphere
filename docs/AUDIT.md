# Audit: eventspherephotobooths.com (current React/Vite build)

This audit is based on the source code reviewed on 2026-05-11.
It supersedes the head-only audit done before source was available.

## Verdict

The current site is a **client-rendered SPA**. The HTML served at every URL is
roughly `<title>Eventsphere</title>` + an empty `<div id="root"></div>`. Every
other SEO issue stacks on top of this. Fixing the architecture (move to static
HTML) gives you 70%+ of the lift; the rest is content and off-site work.

A full rebuild is the right move, not a patch. The list below is what the
rebuild must address, in priority order.

## Architecture (the root cause)

| Finding | Evidence | Impact |
|---|---|---|
| SPA with no SSR/SSG | `main.jsx` mounts `<App>` into `#root`; `App.jsx` uses react-router-dom client routing | Google can render JS but it's slower, deprioritized, and inconsistent. AI assistants (ChatGPT, Perplexity, Claude, Google AI Overviews) see nothing — they don't execute JS when sourcing answers. |
| Per-page `<title>` and `<meta>` never change | No `react-helmet`, no document.title mutation in any page component | Every URL is indistinguishable to search engines |
| Zero structured data | No JSON-LD anywhere in the source | Not eligible for rich results; AI Overviews can't synthesize you confidently |
| No OpenGraph or Twitter card tags | Not present in `index.html` head | Links shared in iMessage/WhatsApp/Slack/LinkedIn show as raw URLs — kills click-through |
| No `<link rel="canonical">` | Not present | Duplicate content risk if URLs ever vary |
| No `robots.txt` or `sitemap.xml` | Not generated by Vite SPA build | Search engines have no roadmap |

## Routing & navigation bugs

| Finding | Evidence | Fix |
|---|---|---|
| Dead `/services` link | `Navbar.jsx` lists `{ to: '/services', label: 'Services' }` but `App.jsx` removed that route | Either restore as a hub page or remove from nav |
| Two sources of truth for pricing | `Services.jsx` has real prices ($375–$700); `Packages.jsx` shows "TBD" everywhere | Pick one source, delete the other; show real prices |
| "Learn More" loops to current page | `Packages.jsx` Ultimate Package "Learn More" links to `/services/packages` from `/services/packages` | Remove or link to a real Ultimate page |
| Mobile dropdown opens on hover only | `Navbar.jsx` Services dropdown uses CSS `group-hover` | Replace with click/tap and a real `/booths` hub page |

## Content & brand

| Finding | Evidence | Fix |
|---|---|---|
| Brand name inconsistency | `Home.jsx`: "Welcome to **Events Sphere**" vs "Eventsphere" elsewhere | Pick one. Recommend "Eventsphere" (matches domain, Instagram, GBP) |
| Service area ambiguity | Hero, footer, and IG say "GTA and Ottawa"; user message said "Toronto + GTA" | Confirm: are you actively servicing Ottawa or is it aspirational? |
| Generic copy | "Capture the magic of your event", "Built on trust", "Tailored just for you" — none of these contain searchable terms | Rewrite with intent keywords: "Toronto wedding photo booth rental", "360 video booth", venue names |
| Testimonials lack credibility | First names only, no event type, no venue, no date | Get permission to use full first name + event type ("Sarah's wedding at Hart House, Sept 2025") |
| Missing print booth in intro | Home intro paragraph only mentions 360 | Update to feature both booth types |
| Broken footer email link | `Footer.jsx`: `href="mailto:hello@eventsphere.com"` displays `eaphotobooths@gmail.com` | Match href to display |
| Logo path issue | `Navbar.jsx` references `/assets/logo.svg` but standard Vite convention is `/logo.svg` in `public/` | Verify file exists and path resolves |

## Performance & UX issues

| Finding | Evidence | Impact |
|---|---|---|
| Full-screen autoplay video on mobile home page | `Home.jsx`: `<video autoPlay muted loop>` covering hero | Crushes mobile LCP, burns user data, no fallback poster |
| `<video controls>` eager-loaded on Booth360 and Gallery | No `preload="none"` | Each video downloads on page load even if user never plays it |
| Carousel mutates DOM directly | `PrintPhotobooth.jsx`: `container.innerHTML += container.innerHTML` | Fights React reconciler, doubles image count, breaks accessibility |
| Carousel ignores `prefers-reduced-motion` | `setInterval` runs unconditionally | Accessibility failure (WCAG 2.3.3) |
| No image optimization | All images served as `.jpg`/`.png`/`.webp` mix without `srcset`, AVIF, or lazy loading | Wasteful bandwidth, poor LCP, poor mobile experience |
| Lightbox modal lacks Escape key, focus trap | `Home.jsx`, `Gallery.jsx` modals close on backdrop click only | Keyboard users get trapped |
| No `loading="lazy"` on gallery images | Not set on `<img>` tags below the fold | Eager loading wastes bandwidth |

## Off-site (separate workstream, runs in parallel with the rebuild)

| Finding | What to do |
|---|---|
| Google Business Profile has only 4 reviews | Build a review-request flow: text/email every past client, link directly to `https://g.page/r/<your-id>/review` |
| Likely no Bing Places / Apple Business Connect listings | Claim both. Free. Each takes 10 min. |
| No WeddingWire, The Knot Canada, EventSource.ca listings | These are vendor directories where Toronto wedding searches happen. Apply to all three. |
| NAP consistency unverified | Once domain is set, verify Name/Address/Phone match across GBP, IG bio, footer, all directories |

## What's actually good and worth keeping

- The brand color (`#ed70c0`) is distinctive and works
- Tailwind is the right styling choice (we'll keep it in Astro)
- Formspree integration is fine for now (no reason to swap until you want branded emails)
- Two Instagram accounts (`@eventsphere.to`, `@eventsphere.ott`) is the right call for two regions
- The icon choices (FaTags, FaHandshake, FaPaintBrush) on the value-prop section are fine
- The page hierarchy intent (booth-type pages + packages + gallery + contact) is roughly correct

## Things I can't verify without deeper access

These should be checked by Claude Code in Phase 0 using Playwright + Lighthouse:

- Real Lighthouse scores (perf, SEO, a11y, BP) on mobile + desktop
- Whether existing image assets are actually present at the referenced paths
- Whether Formspree env var is actually set in the deployed environment
- Current Search Console traffic (need GSC access)
- Current GBP completeness % and category list
- Backlink profile (need Ahrefs/Semrush or free fallbacks)
- Whether DNS has any existing email/MX configuration to preserve

## Rebuild priority (what fixing what gets you)

1. **Static rendering (Astro)** — fixes invisible-to-crawlers problem
2. **Per-page metadata + JSON-LD** — fixes "every page looks the same" problem
3. **Real prices, single source of truth** — improves inquiry conversion
4. **Real testimonials, real event photos** — improves trust signals
5. **Location-specific pages (Toronto, Ottawa, GTA cities)** — captures intent searches
6. **Image optimization (AVIF/WebP + srcset)** — fixes mobile LCP
7. **Schema markup on every page** — improves AI Overview eligibility
8. **GBP optimization + review-request flow** — improves Map Pack ranking
